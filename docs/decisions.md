# Decisions

- 2026-11-04 — One web app (PWA) on the droplet, Go + SQLite + Vue, following Kindred Nights' tooling. No native apps.
- 2026-11-04 — books.jamescwill.com with books.mathdad.me as a full alias, not a redirect. Passkeys are per name; a setup code adds the first passkey on each.
- 2026-11-04 — Metadata from Library of Congress, Open Library, and Google Books, merged field by field; blanks are filled later, owner edits are never overwritten.
- 2026-11-04 — Copy barcodes are `HL` plus the five-digit copy number, Code 128; Avery 5167 for barcodes and 5195 for spine labels on the Brother HL-L2460DW.
- 2026-11-04 — Covers are stored as JPEG through the standard library, not WebP: webp-go-pure v1.2.0 crashed (an access violation in its lossy assembly at effort 4) on a 333×500 cover during the first import. Effort 8 passed the same probe; Kindred Nights uses effort 8.
- 2026-11-04 — The library list is sent whole and searched, filtered, and sorted in the browser: a household's few thousand books are one small response.
- 2026-11-04 — Free sources only: no paid API (ISBNdb) and no scraping of one. Gaps are filled by hand on the Edit page, or by the owner's cover photo.
- 2026-11-04 — Google gives text only. Its image host (books.google.com/books/content) answers the droplet with a "Sorry" page (403) while serving a home connection, so a Google cover could be shown but never kept. Covers come from Open Library or the owner's photo; Google thumbnails appear in search results for recognition only.
- 2026-11-04 — Read-only sharing by revocable share links, as phase 3 after scanning. The server leaves out what is the owner's alone (prices, provenance, notes, borrowers), so nothing private reaches a visitor's browser at all.
- 2026-11-04 — Cover photos are straightened by four corners the owner places on the book's corners (a projective warp in the browser), and the editor fills the screen on a phone. The photo is laid out by CSS and percentages, never by measuring the dialog: a dialog measured as it opens has no width.
- 2026-11-04 — Automatic cover detection uses OpenCV.js (@techstark/opencv-js 4.12) in a Web Worker. Its Emscripten bindings build functions with `new Function`, which the site's policy forbids; the worker's own script is served with a policy that allows it, so no page loosens its own, and the detection runs off the main thread. It is loaded only when the cover editor opens.
- 2026-11-04 — Scanning in Add a shelf queues each ISBN on the server and a worker adds the book, so scanning never waits on a lookup; the queue is the review list, kept until the owner marks each scan done.
- 2026-11-04 — The first import is the Bookshelf app's CSV (365 books). Its shelves become sections and its categories become subjects; genres stay the owner's own list.
- 2026-11-04 — A share link's token is only in the address it was sent as: opening it puts the link's id in a fresh session and redirects to the library, so the token leaves the address bar. Every request checks the link is still there and running. The API opens two operations to visitors (the list and a book), refuses the rest with 403, and the server blanks the owner's fields on a book before it leaves. Visitors are rate-limited per link and address; covers are not counted.
- 2026-11-04 — Loans are on copies and borrowers are named, as series and sections are: typing a new name when lending adds the borrower. A copy is with one borrower at a time (a unique index on open loans), returned loans stay as the history, and a copy that is out cannot be removed until it is back. Removing a borrower removes their history with them, and asks first. Overdue is reckoned in the browser against the device's day, not the server's: a loan due today is not late in the evening.
- 2026-11-04 — Courses list copies, not editions, each required or not; the term is a season and a year so courses sort in the order they were taken. Courses and everything about loans but "on the shelf or out" are the owner's alone; a visitor's book leaves them out on the server.
- 2026-11-04 — Six places in the navigation (Library, Scan, Add, Loans, Courses, Settings). Import moved to a button on Add, since importing is adding many at once. Six names need about 54rem beside the brand, so the top bar starts at 64rem and tablets keep the bottom tabs.
- 2026-11-04 — A PrimeVue Select is named by `aria-labelledby` pointing at its FormField label (`<id>-label`): a label's `for` reaches only form elements, and a Select's box is a span, so screen readers were reading the chosen value ("No season") as its name.
- 2026-11-04 — Each edition's author line comes from one view, `edition_authors`, which the library list, the scan list, the loans, and the courses all read.
- 2026-11-04 — Shelving is a rule on each section (Dewey, author, or series, with a prefix), not one setting for the library: it is what PLAN's "Dewey for nonfiction, fiction by author, manga by series" comes to with the owner's own sections, and a new section can follow any of the three. Call numbers are worked out from the rule and the book, never stored, so a corrected Dewey number or series changes the next label printed.
- 2026-11-04 — Label PDFs are drawn by the server with a small PDF writer and Courier, one of the fonts every PDF reader carries: no library, nothing embedded, and a monospaced face makes centring and cutting to fit exact. The Code 128 encoder (set B) was checked by decoding a full rendered sheet of 80 labels with zxing. Titles beside the barcode use WinAnsi; a character it lacks prints as a question mark.
- 2026-11-04 — Avery 5167's layout is the one gLabels and LibreOffice agree on (0.28125" side margin, 2.0625" column pitch, 0.5" top margin). No reliable source gave 5195's, so it shares 5167's columns with ⅔" rows, as Avery's 1¾" sheets do; everything prints 2 mm inside each label, and the alignment sheet confirms or corrects it per printer.
- 2026-11-04 — Labels wait for a full sheet and print in shelf order, so a sheet of spine labels goes on in one walk along the shelves. Printing opens the PDF in a new tab; the owner then says whether it printed well before the labels leave the queue. A partial sheet can be printed, with a note that the rest of the sheet should not go through a laser printer again.
- 2026-11-04 — Scanning one of the owner's labels in Check opens the book at that copy, marked and focused; in the lending dialog it picks that copy. A list in a query is sent comma-separated, as huma reads it, set once on the API client.
- 2026-11-04 — The owner shelves without sections. Migration 00007 removed the three the library began with (Fiction, Nonfiction, Manga and Light Novels), which the Bookshelf import had filled from its shelves, and the import no longer reads its shelves. A copy without a section follows the Dewey rule, so spine labels read `823.92 MCD`; sections the owner makes later can take any rule.
- 2026-11-04 — The library search looks in subjects, genres, everyone credited (editors, translators, illustrators), and the LC class, as well as the title, authors, series, and numbers it covered: the owner searches by subject.
- 2026-11-04 — Descriptions are plain text everywhere. One cleaner (`lookup.PlainText`) turns markup into paragraphs for every source and the import, including the Bookshelf export's `&&L`/`&&R`. The export also cut descriptions off at 1500 characters: such a description is not the import's whole text, so the background lookup may replace it with a source's longer one, the one exception to "an import's value is never overwritten". One that no source has whole keeps the source `bookshelf-cut`, and the book's page says so. Migration 00008 queued the 46 affected books.
- 2026-11-04 — Documents keep their files outside `/media`, under random names, served only through the API, which checks the reader: the owner, or a visitor when the owner has shared that document. A file is known by its first bytes, never by the type the browser sends.
- 2026-11-04 — Text is read by a separate service, the same binary as `read-text` under its own unit: idle CPU and disk priority, a CPU and memory cap, no network. It uses pdftotext for a PDF with text and Tesseract for photos and scanned pages, three tries a file, and never replaces text the owner typed. The web server never waits on it.
- 2026-11-04 — Full-text search is SQLite's FTS5, one row a document (its details and its files' text), prefix matches on every word. The search query is the one SQL statement outside sqlc: sqlc's SQLite parser does not know that an FTS5 table's own name is a column, which MATCH, snippet, and rank need. Writes to the index go through sqlc, by a document_id column rather than the rowid.
- 2026-11-04 — Documents live under the Library, in a Documents tab beside Books, rather than in a seventh place in the navigation. Citations (APA, MLA, Chicago) are made in the browser from the record and copied as HTML and text, so a word processor keeps the italics.
- 2026-11-04 — The Open Library covers API the owner pointed to is the one covers already come from, by cover ID (`/b/id/…-L.jpg`): lookups by ISBN through it are limited to 100 every five minutes, and by ID are not.
- 2026-11-04 — The shelf planner works from a proposal: the copies in shelf order, each shelf filled to a target (80% unless set). Put to use, each shelf keeps where its first book falls in the order (its shelving, as JSON), and a copy goes to the last shelf that starts at or before it; a new book takes the room left on its shelf instead of pushing every later book along, and a shelf past full is shown so. Planning afresh replaces the starts. A book taller than the shelf its turn comes on goes to the oversize shelves rather than to a later, taller regular shelf, so a shelf's range never has gaps a reader cannot see.
- 2026-11-04 — A book's height and thickness are measured where a source gave them (239 heights, 40 thicknesses of 366) and worked out otherwise from its format and pages, at rates the measured books bear out: about 0.065 mm a page and 3 mm of cover for a paperback, 0.05 mm and 6 mm for a hardcover. The planner counts the estimates and the owner can measure any book on its Edit page.
- 2026-11-04 — Shelves are measured in inches or centimetres, as the owner chooses on the page (remembered on the device), and kept in whole millimetres.
- 2026-11-04 — With sections gone, every copy follows the Dewey rule, so the books without a Dewey number (94 of 366) come first in shelf order, by author: nothing sorts before something. A book with neither a number nor letters in its title is named by its title on a shelf's range.
- 2026-11-04 — Corner braces are two numbers on a shelf, how far a brace hangs down and how far it reaches in, the same at both ends since the owner's are (1¼–1½" tall, ¾" wide, full depth, under every shelf). A book that clears the brace stands anywhere; a taller one cannot stand in the first or last brace's width. So a tall first book starts past the brace and the shelf says how much to leave empty, and a tall book that would reach the far brace goes to the next shelf. A brace must be shorter than the shelf and narrower than half of it; half a brace (one number without the other) is no brace. Migration 00010.
- 2026-11-04 — One choice of inches or centimetres serves every length in the app, typed or shown (shelves, braces, a book's size on its page and its Edit form), kept per device in the browser like a reading preference rather than on the server. Storage stays whole millimetres: most lengths arrive metric (208 of 239 heights are the Library of Congress's centimetres), and a millimetre is finer than anyone measures a shelf.
- 2026-11-04 — A length shows as the plainest number that comes back to the same millimetres, trying whole, half, and quarter inches before tenths and hundredths: 279 mm is 11 in, not 10.98, and 32 mm is 1.25 in. Reading stops at a tenth (an estimate of 212 mm is 8.3 in, not 8.35); a field goes to hundredths and keeps what was typed while it still means the same millimetres, so it never changes under the cursor. A test checks every length from 1 to 1000 mm comes back whole in both units.
- 2026-11-04 — PrimeVue's number steppers (the + and − beside a number field) were 40 px wide; they now take the 44 px target size every control has.
- 2026-11-04 — Scan is one flow instead of Check and Add a shelf: the owner had used only Check, which shows one result, and "Add a shelf" read as the shelf planner's shelves. Every scan joins the server's queue and is looked up in the background, but held as found until the owner adds it (one, or all at once), with the section and new or used chosen at that moment. The queue keeps what the sources said, so adding does not look the book up again. Migration 00011 rebuilds `scans` for the `found` and `adding` states and the kept lookup.
- 2026-11-04 — Open Library's subjects, used only when neither the Library of Congress nor Google has any, come from every edition of a work in every language ("Socialisme", "Revolutie", one Russian party's name romanized six ways on *What Is to Be Done?*). Each is now checked against the Library of Congress Subject Headings (id.loc.gov, free, no key) and kept only as an English heading it knows, in its authorized form; the answers are cached like the sources'. Translation was weighed and left out: the foreign subjects stand beside their English ones on the same record, and no translator turns a romanized name into English.
- 2026-11-05 — Export is two files from Settings: a CSV, a row a copy with the book's details beside it, for a spreadsheet (a byte order mark so Excel reads it as UTF-8), and one JSON file of everything the owner entered (books with their copies, borrowers and loans, courses, documents' details, bookcases, shelving rules). Covers and document files stay out of both; the backups keep them.
- 2026-11-05 — The nightly backup keeps the covers and documents' files beside the database snapshot, as hard links into a dated directory: both are written once under new names and never changed, so a day costs no room until a file is let go, and the backups grow with what the library deletes rather than with its size. The copy off the droplet is the owner's choice of the PC: a scheduled task pulls the newest snapshot into OneDrive daily and keeps 14 days. No new account and no monthly cost; it runs when the PC is on, and a missed day runs at the next start.
- 2026-11-05 — One Import takes Bookshelf, Goodreads, and LibraryThing exports, told apart by their columns (CSV or tab-delimited). A book already here keeps its details and gains a link to its page in the other app and the reading it lacks; a book the other app does not mark as owned comes in only when asked, and one on a wish list or to-read shelf never does, since the library is of books in the house. Import refs keep the other app's address. LibraryThing publishes no list of its export's columns, so its columns are read by name with the variants known; Goodreads' are fixed.
- 2026-11-05 — Hardcover's API (the owner's free token, `HL_HARDCOVER_TOKEN`) joins the lookup for covers, after Open Library's, and for a series when no other source names one. Measured against the library: it had a cover for 46 of the 84 books without one, and for 3 of the 4 whose only cover was the owner's photo (which a lookup never replaces; the owner may choose its cover on the book's page). Its series names are no better than Open Library's for manga (some are Japanese), so a non-Latin series name from it is left out, and any series named in two scripts keeps its English half. Migration 00013 merged The Ideal Sponger Life's three series and renamed High School Prodigies; 00014 queued the books without a cover.
- 2026-11-05 — The 1.0.0 readiness pass checked every page and dialog at 390 and 1280 pixels in both schemes against the AAA rules with a script in the page, and the code for dead and doubled work. Fixed: small text kept lines 1.43 apart (Tailwind's own) and now keeps 1.5; three pieces of prose ran past 70 characters; links standing alone, not in a sentence, take `link-target` for their 44-pixel reach. Removed: four queries, three functions, two type re-exports, unused rules and tokens. Made one way: a cover is `{id, widths}` in every answer; device storage is `app/remember.ts`; a length field is `LengthField`; the place sentence, marking a copy back, and the label kinds' names are each written once; the book and document pages take `PageHeader`, the pages before sign-in `PublicPage`; a book's copies are a DataTable; the Scan page's shared fields are `CopyFields` in brief. The lookup's rules (what a code is, the series' Dewey number) moved from the handler into the catalog, and the last raw queries into sqlc.
- 2026-11-05 — The pages before signing in (sign-in, setup, a link that has ended) have no skip link: each is a main alone, with no bar or navigation to bypass (WCAG 2.4.1 asks for a way past repeated blocks, and there are none).
- 2026-11-05 — Literal colors stay in `index.html` and the web manifest, which take no tokens: the theme color is given for both schemes in `index.html`, while the manifest, which has one theme and one background color, keeps the light scheme's.
- 2026-11-05 — `VACUUM INTO` in the backup is the second statement outside sqlc, beside the FTS5 search: sqlc does not know it, and it is the one consistent copy SQLite makes of a live database.
- 2026-11-05 — A document takes files as they are (a PDF, or images a scanner made, several at once) through "Add a PDF or image", and photos of pages through `CoverPhoto`, which straightens them. The search results on Add a book are a choice among candidates, as `CoverChoices` is among covers, so they are buttons rather than a table of records.
- 2026-11-05 — Barcode labels go inside the front cover on Avery 6467, which has 5167's layout and a removable adhesive: 5167 and 5195 are permanent and leave residue on a book. Spine labels remain a kind of their own on 5195, off until the owner settles on a shelving scheme. Each kind is turned on or off on the Labels page; an off kind's labels keep joining its queue, so turning it on later finds every copy waiting. Migration 00015 turned spine labels off.
- 2026-11-05 — A wanted book is an edition with no copy and the day it was wanted (`editions.wanted_on`), not a list apart, so it has the same lookup, cover, and page as any book; its first copy takes it off. It stays out of the library's list, counts, and labels, and a scan of it says it is wanted. An import puts Goodreads' to-read shelf and LibraryThing's wish list on it when the row has an ISBN; a wanted row without one is left out, since it could match nothing. Visitors see it, as a gift list. Migration 00016.
- 2026-11-05 — A copy that leaves the house (lost, sold, donated, given away, discarded) is marked gone with the day and a note, not removed: removing it would take its loans with it, and a copy can come back. A gone copy leaves the shelves, the label queue, the counts, and a visitor's view; one out on loan must come back first. A shelf check scans each book on one shelf, by its label or ISBN, and marks it seen that day; what is not found is listed with a way to mark it gone, and a book from another shelf says where it belongs. Migration 00017.
- 2026-11-05 — The Series page counts gaps between volume 1 and the highest number had, and a wanted volume is not a gap. A series whose highest number is past 200 (numbered by year or by issue) shows only its next number, rather than hundreds of gaps. Renaming a series to the name of another merges the two, since the owner would otherwise have to move each book by hand.
- 2026-11-05 — Earlier reads are rows of their own (`readings`), and the work still holds the read in progress or the latest, so nothing that read the work's status changed. "Read it again" moves the latest read into the history and starts a new one. The Reading page counts books and pages finished each year from both. Migration 00018.
- 2026-11-05 — Missing details lists the books lacking a cover, Dewey number, height, thickness, pages, format, publisher, date, or description, with a count for each. Looking them up again queues the chosen books for the background lookup, which fills blanks only.
- 2026-11-05 — Overdue reminders come from a calendar feed (iCalendar) at a secret address the owner makes, replaces, or turns off on the Loans page, kept as its hash like a share link: the phone's own calendar reminds, and the server sends nothing and needs no mail or push service. Each open loan with a due date is an all-day event with an alert at 9 in the morning. The feed is rate-limited with sign-in, and its events are named by loan, never by the host asked. Migration 00019.
- 2026-11-05 — The service worker keeps the app's shell (from the network first) and its built files (named for their content, let go when a new build's shell arrives), so the installed app opens without a connection. The owner's device keeps the library list in the browser's cache storage, replaced each time it loads, and forgotten on signing out. Offline, the Library lists the books as of that day and Scan says whether an ISBN is had or wanted; nothing joins the scan queue until the server answers. API answers, covers, and documents never pass through the worker, and a visitor's device keeps nothing.
- 2026-11-05 — Lint and CI scan for known vulnerabilities: govulncheck (pinned) on the Go code, `npm audit` at every severity on what ships and from high up on the build and lint tools. The first scan found nothing the app runs. It reported golang.org/x/crypto's openpgp in a required module that the code never calls, and a moderate minimatch in the typescript-eslint chain, which reads only our own files. Both wait for their packages' own fixes rather than forced versions.
- 2026-11-05 — End-to-end tests are Playwright, against the real binary built and migrated into a temporary folder on port 8140, signed in through `dev-session`. They drive the Edge already on this machine, so there is no browser to download, and Chrome on CI. One worker, since the tests share a library. `task test` runs them after the Go and web tests; `task e2e` runs them alone.
- 2026-11-05 — Open Library's "large" cover is cut to 500 pixels high, and many uploads are far bigger (one in this library is 2023 × 3253), so a lookup offers each of the edition's pictures as uploaded, by cover id without a size. Search results carry a thumbnail to show and the full-size cover to keep. The cover chooser names each cover's source and its size in pixels, as the browser finds it on loading, since the sources do not say. Hardcover's covers were blank in it because the image policy lacked their host, `assets.hardcover.app`; it is now allowed. A cover chosen from the chooser was recorded as from "a link"; a stored cover's source is now named by its link wherever it was chosen. Migration 00020 gives the lookups kept in the scan queue the new shape of a cover choice, a link and its source.
- 2026-11-05 — "Look up again" on a book still fills its blanks at once, and now also offers each detail the sources give otherwise, beside what the book has and where each came from, to take or leave one by one. A taken value keeps its source's name, so a later lookup goes on filling only blanks. Spacing is no difference, nor a length within a centimetre (the Library of Congress measures in whole centimetres); people are offered only when a source names someone the book lacks, since one that names fewer (no translator) knows less. The background lookup is unchanged: it fills blanks and offers nothing.
- 2026-11-05 — A book's reading status has its own route, used by its page and by a choice on each row of the library list: begun or finished, it keeps the device's day where it has none. "Mark read" on the Series page marks every book of the series the house has, not the wanted ones, and gives none a day: it records the past, and a made-up day would put old reads in this year's count.
- 2026-11-05 — The library list keeps its page, rows per page, and order in the store with its search and filters, so going back from a book lands where the owner was; a new search or filter starts it at the first page. A title that is one long word (Euthyphro/Apology/Crito/Meno/Phaedo) breaks to fit a phone's column in every table, and the page audit now measures each table's own frame, which scrolled sideways without the page doing so. A toast's close button is the 44-pixel target size; it was 28.
- 2026-11-05 — Documents take subjects, as books do. A DOI brings them from OpenAlex (free, no key): its keywords it is fairly sure of and the work's main topic, ahead of the journal's broad fields from Crossref, which names none for chapters. OpenAlex's older concepts are left out: tagged by machine across the index, they gave a chapter on causation "Domain (mathematical analysis)". The subjects join the full-text index, which migration 00021 rebuilds with a column for them, since an FTS5 table takes no new column. A new document takes its PDF or scanned images as it is added; photos of pages are still taken on its own page.
- 2026-11-05 — EndNote libraries come in through its XML export (File, Export, as XML), not the `.enl` file: that is EndNote's own database, open in EndNote while it runs, in a form EndNote does not publish and changes between versions. Books (books, edited books) join the library through the other apps' path, matched by ISBN and kept by an import ref; articles, chapters, and other papers become documents, kept by a document import ref (migration 00022) or matched by DOI. EndNote marks no book as owned, so the import's switch for books not marked as owned became a choice of where they go: left out, the shelves, or the wishlist (which takes a book with an ISBN). The owner's library was filled from the Library of Congress catalog, so its records carry the catalog's ways: "Last, First, dates" names are written as read; "Title : subtitle" is split, and an English title in sentence case is capitalized as its cover is; the catalog's Notes (record number, size, bibliography) of a record with the catalog's accession number are left to the lookup, and only research notes come in; the call number becomes the LC class. A book with an ISBN takes its subjects from the lookup, as the catalog writes them, rather than EndNote's keywords, which keep only the words ("Quantum theory Popular works."); one without keeps them. The library has no PDFs attached, so the import brings no files.
- 2026-11-05 — Leaving a page that was a step on the way leaves nothing for Back to walk through. Saving or cancelling an edit goes back to the record's page when that was the page before, or puts the record in the edit's place; a new book or document takes the add form's place; a record removed sends Back to the page before it, never to itself or its edit. `returnTo` and `goBack` are the one way to do it.
- 2026-11-05 — The deeper pages carry a breadcrumb trail over their title, part of `PageHeader`: Library › a book's series › the book over its Edit page, Documents › a document, Courses, Shelves, and so on. It names only the pages above, as GOV.UK's does, since the title says where this is. PrimeVue's Breadcrumb was weighed and left: it puts each separator in the list as an item of its own, which a screen reader counts, and its plain links reload the app. A series' crumb, and each series on the Series page, opens the library's list searched for it (`/?search=`), which the list takes into its own search.
- 2026-11-05 — Marking a book read gives it no finish day: the owner marks old reads as often as new ones, and they all landed in 2026. The day is entered on the Edit page when it is known. Marking a book Reading still gives it today as its start, since reading is now. Migration 00023 cleared the finish day of the 22 books marked read on 2026-11-04 and 05 with no start, which the old rule had dated.
- 2026-11-05 — The colors match the device by default, as before, and Settings offers Light or Dark instead, kept on the device like the other preferences. PrimeVue's dark scheme is keyed to one class on the page's root (`scheme-dark`) rather than to the device's setting; `app/scheme.ts` sets it from the choice, or from the device while matching it, as that changes. Every token comes from PrimeVue's variables, so the one class turns the whole theme, and a forced scheme was checked to give the very colors the device's gives. The browser bar takes the chosen scheme's color from `index.html`, and the page declares its `color-scheme`, so scrollbars and the browser's own controls are dark in the dark scheme (they were light before).
- 2026-11-05 — A table row's link is a target of the full 44 pixels whatever its words, as the trail's links are: a book titled "Mind" made a 38-pixel one.
- 2026-11-05 — A series has a page of its own (`/series/:id`), and the Series list's rows open it; its actions moved there with it. The library's list no longer takes a search from its address, which only the series links used. On it a book is taken out of the series, and the whole series is said to be none: Open Library gives publishers' lines as series (Penguin classics, Dover thrift editions, An HBJ modern classic), and the library had 86 series, many of them so. A series said to be none keeps its name with the day (`series.dismissed_on`), so no lookup or import puts a book in it again; the owner typing the name makes it a series again. A book taken out has its series marked as the owner's, empty, and `fillBlanks` now leaves every field the owner emptied as it is, which the Edit form's cleared fields wanted too.
- 2026-11-05 — "Look up again" asked the sources only when their kept answer was over 90 days old, so it mostly gave back what the first lookup had; it now asks each source afresh. The background lookup still uses the kept answers. A series' page looks its books up again one after another from the browser, with their suggested changes offered together at the end, rather than as work on the server: each lookup is a request of a few seconds, the owner can stop between books, and the blanks each fills are kept as it goes.
- 2026-11-05 — Series names: Open Library writes the number into the name ("Malazan book of the fallen -- bk. 9", "The Malazan Book of the Fallen: Book 2", "Book six of the Malazan book of the fallen"), which made five series of one. The parser reads those forms, and a number in words. A series from a lookup or the form joins the library's series of the same name written another way ("Broken Empire", "The Broken Empire"); the series already split stay as they are until the owner renames one into the other or looks it up again. "Look up again" offers another series with its number, since the number belongs to the series.
